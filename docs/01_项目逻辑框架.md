# 01 项目逻辑框架

## 1. 为什么做这个项目

博士申请材料里，真正有分量的通常不是「我用过 ROS2 / PyTorch」，而是
「我针对一个明确的问题，提出了可验证的方法，并做了受控实验」。本项目把这句话
落成一个具体的研究闭环：

> **问题**：杂乱遮挡场景下，机器人的单个固定视角不够用。主动选择视角
> （Next-Best-View）能否提升视觉推抓系统的清理效率？
>
> **方法**：在经典 VPG（Visual Pushing & Grasping）框架上，引入由不确定度
> 图驱动的「换视角」动作。
>
> **证据**：与无视角消融、随机视角、贪心基线对比，报告多随机种子的
> 均值±标准差。

## 2. 创新点的诚实定位

这是两个成熟方向的交叉，而不是无中生有的新发明：

- **VPG**（Zeng et al., IROS 2018）：固定俯视视角下的推+抓像素级 Q 学习，
  本项目的方法主干与基线。
- **Multi-View Picking**（Morrison et al., ICRA 2019）：主动换视角后抓取，
  但没有推、没有学习式视角选择。

本项目填补的缝隙是：**把「选择视角」做成学习型动作放进推抓策略**，并用
不确定度图做状态表征和奖励信号。写申请材料时建议的表述是「系统复现并改进了
VPG，在主动感知方向做了受控扩展」，而不是「首创」——前者可信，后者容易被
面试追问到失分。

## 3. 关键设计决策（为什么这样设计）

### 3.1 用「眼在手」相机而不是固定顶视相机

如果相机固定在正上方，场景永远一目了然，「主动看」就没有意义。腕部相机从
默认视角只能看到部分场景（前排物体挡住后排），于是换视角有真实价值，同时
又只用一个机器人、一个相机，工程复杂度可控。

### 3.2 世界模型 = 高度图 + 不确定度图

高度图是 VPG 的标准表征，做多视角融合很自然。不确定度图是项目的原创点，
由三个可解释的因子合成：

- **空洞**：当前世界模型里从未观测到的格子；
- **陈旧**：信息年龄，很久没被直接观测到的格子；
- **边缘**：高度突变，是遮挡边界的签名。

换视角的奖励直接定义为「不确定度下降量」，智能体学到的是**信息增益**。

### 3.3 双快照记忆，而不是永久累加

多视角融合若把历史观测永久保留，物体被抓走后高度图会出现「幽灵」。本项目
用两个快照解决：默认视角快照（每次动作后刷新）+ 备用视角快照（保持到下一次
操纵前）。操纵（抓/推）会清空备用快照，因为世界变了。

### 3.4 手写运动学，不用 MoveIt

MoveIt 配置对新手是黑盒且容易坏。本项目从 URDF 运行时解析关节链，手写
FK 与数值 IK（scipy least_squares + 多重启动），运动学永远与仿真机器人一致，
同时 FK/Jacobian/IK 本身就是可以在面试中讲的硬知识。

### 3.5 奖励设计

| 动作 | 奖励 |
|---|---|
| 抓取成功（物体入盒） | +10，清空全场景额外 +5 |
| 抓取失败 | -0.3 |
| 推动 | clip(30×平均高度变化 − 0.1, −0.2, 1.0)，鼓励真实改变 |
| 换视角 | clip(2×不确定度下降 − 0.05, −0.05, 1.0)，即信息增益减成本 |

## 5. 能力边界（面试时被问到要能答）

- 场景是小规模桌面（≤8 个无纹理基本体），不是任意家庭环境；
- 抓取是竖直俯冲式，不做 6-DoF 任意姿态抓取；
- 视角集合是离散的 4+1 个预定义位姿，不是连续视角规划；
- 这是纯仿真研究，sim-to-real 是讨论项而不是交付项。

如实说边界比夸大更好：它展示的是「我知道问题的范围在哪里」。
