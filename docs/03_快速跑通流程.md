# 03 快速跑通流程（操作书）

从零到「能写进简历」的完整流程，每一步都有预期输出和验收标准。
建议按顺序执行，不要跳步：每一步都在验证系统的一层。

## 第 0 步：理解目录

打开 `src/`，先记住七个包各管一件事（详见 docs/04）。你可以不看懂代码，
但要能在 `docs/04` 的结构图里指出「感知在哪、学习在哪」。

## 第 1 步：编译

```bash
cd ~/ros2_ws/src/active-grasp
bash scripts/build.sh
```

预期输出：`colcon build` 结束显示 `Summary: 7 packages finished`（或类似），
没有红字 error。

验收：`ls install/` 能看到 ag_ 开头的目录。

## 第 2 步：启动仿真世界（只开 Gazebo）

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch ag_bringup sim.launch.py
```

预期输出：

1. Gazebo 窗口出现一张桌子、蓝色回收盒、四条低矮边界墙；
2. 机械臂在桌子一角，几秒后自动运动到「home 位姿」；
3. 终端依次打印 `world manager ready`、`perception ready (camera calibrated)`、
   `execution ready`。

**这是全项目第一个关键验收点**：如果三条 ready 都出现，说明相机插件、
ros2_control、TF、IK 全部正常。若卡住，看 docs/06。

## 第 3 步：用手动命令验证单步动作

开一个新终端（先 `source install/setup.bash`）：

```bash
# 生成 4 个随机物体
ros2 service call /world_manager/reset_scene ag_interfaces/srv/Reset \
  "{num_objects: 4, randomize_objects: true}"

# 观察一次，确认状态图有数据
ros2 service call /perception_node/observe ag_interfaces/srv/Observe \
  "{auxiliary_view: false}"

# 让机器人看第 1 个备用视角（俯视）
ros2 service call /execution_node/move_view ag_interfaces/srv/MoveView "{view_id: 0}"

# 回到 home
ros2 service call /execution_node/go_home std_srvs/srv/Trigger
```

验收：Gazebo 里机械臂先看桌面、再移动到俯视位姿、最后回 home；每个 service
调用都返回 `success: true`。

## 第 4 步：跑贪心基线演示（端到端闭环）

关掉第 2 步的终端，然后：

```bash
bash scripts/run_demo.sh
```

预期输出：Gazebo 中出现 5 个物体，机械臂开始抓最高的物体放进回收盒，抓不住时
会推它。终端逐行打印：

```
[demo] GRASP cell (24, 23)
[demo] reward=9.98 cleared=1/5
```

验收：能看到至少一次完整的「靠近 → 抓取 → 入盒 → 回 home」动作序列。
这说明**感知 + 运动学 + 执行 + 环境封装**整条链路通了。这也是你演示视频里
「pipeline 已跑通」的素材。

## 第 5 步：观察内部表征（理解研究在做什么）

另开终端：

```bash
ros2 service call /perception_node/observe ag_interfaces/srv/Observe \
  "{auxiliary_view: false}" > /tmp/state.yaml
```

返回的高度图/不确定度图是 `sensor_msgs/Image`。想看图像的话，训练脚本和
单元测试里有现成逻辑；最快的方式是在 `tests/test_fusion.py` 里加两行可视化
代码（学有余力再做）。

验收：能说出「高度图里高的格子 = 物体；不确定度高的格子 = 没看到或被挡住的
地方」。

## 第 6 步：无头训练

```bash
bash scripts/train.sh
```

预期输出：

- Gazebo 以无头模式启动（无窗口），物理以 CPU 最大速度运行；
- 每 5 个回合打印一行 `ep ... clearance=... steps=... reward=... views=...`；
- `results/training_log.csv` 持续写入；
- 每 50 回合保存 `checkpoints/agent_*.pth`。

建议先跑 50–100 回合确认流程稳定，再放一晚上跑完整训练。CPU 上的参考速度：
每秒约 0.3–1 个动作，400 回合大约几小时。

验收：CSV 里 clearance 从接近 0 逐步爬升（有噪声是正常的），`views` 列不再
恒为 0——说明智能体学会了使用视角动作。

## 第 7 步：评估

```bash
bash scripts/evaluate.sh checkpoints/agent_final.pth
```

预期输出：2/4/6/8 物体场景的清理率均值±标准差、平均步数、视角使用率。

验收：训练后策略的清理率明显高于第 4 步的贪心基线（如果持平，回到第 6 步
多训一会儿，或按 docs/05 调参）。

## 第 8 步：三个消融实验（产出研究报告）

| 实验 | 做法 | 回答的问题 |
|---|---|---|
| 无视角消融 | 训练时把 view 动作从动作空间去掉 | 主动视角到底有没有用 |
| 随机视角 | 视角动作改成随机选择 | 是「会选」还是「随便看看也行」 |
| 贪心/随机基线 | `demo.py` 与 `evaluate.py` | 学习是否优于规则 |

具体怎么改代码、怎么报告结果见 docs/05。

## 第 9 步：产出行李箱

1. 录演示视频：`ros2 launch ag_agent demo.launch.py`，用系统录屏；
2. 画学习曲线：`python3 scripts/plot_training.py`；
3. 写 README 的 GIF/截图：训练前 vs 训练后、高度图 vs 不确定度图；
4. 按 docs/08 写简历条目。

全部做完，这个项目在简历上就是一条完整的研究经历。
