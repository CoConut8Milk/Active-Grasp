# 06 常见问题排查

按症状查表。原则：**先确认现象，再看日志，一次只改一个变量**。

## 环境层

| 症状 | 原因与处理 |
|---|---|
| `setup_wsl2.sh` 下载很慢 | 换 apt 镜像源（清华/阿里），重跑 |
| pip 装 numpy 报错 | 网络问题；用 `-i https://mirrors.aliyun.com/pypi/simple/` |
| `rosdep init/update` 报 GitHub raw 连接失败 | 网络拦截了 `raw.githubusercontent.com`（与 WSL 安装超时同一原因）。rosdep 只是辅助工具，**不影响本项目编译运行**；最新版 `setup_wsl2.sh` 会自动改用中科大镜像重试 |
| 跑脚本报 `AMENT_TRACE_SETUP_FILES: unbound variable` | ROS Humble 的 `setup.bash` 与脚本里 `set -u` 的已知冲突；已修复（source 前临时关闭 nounset），`git pull` 后重试即可 |
| 运行 launch 报 `'NotImplementedType' object is not iterable` | launch 条件写法不兼容 Humble（已修复 `sim.launch.py`），`git pull` 后重试即可 |
| Gazebo 打开后没有桌子/回收盒，机器人摔在地上 | `ag_gazebo` 的 world 文件没被安装进 `share`（已修复 `setup.py`）；`git pull` 后重新 `bash scripts/build.sh` 再跑 |
| 机械臂瘫倒、spawner 一直等 `/controller_manager` | Gazebo Classic 下 controller_manager 由 `libgazebo_ros2_control` 插件内建，不能再单独启动 `ros2_control_node`（已修复）；`git pull` 后重新 build 再跑 |
| 节点启动即崩溃（execution_node / perception_node） | 参数文件里用了 ROS 2 不支持的嵌套列表/字典，且 `use_sim_time` 被重复声明（均已修复）；`git pull` 后重新 build 再跑 |
| 插件报 `Couldn't parse parameter override rule` | URDF 里的 XML 注释/换行会破坏插件注入参数（已修复：launch 自动剔除注释并压成单行，与 xacro 输出对齐）；`git pull` 后重跑 |
| `demo`/`train` 报 `unrecognized arguments: --ros-args` | Python argparse 与 launch 附加的 ROS 参数冲突（已修复）；`git pull` 后重跑 |
| 夹爪不动：`Skipping joint in the URDF named 'finger_left'` + `Failed to activate controller : gripper_controller` | Gazebo Classic 默认把固定关节"合并"进父连杆，`tool0` 无惯性质量时连挂在它下面的两根手指关节一起被删掉。已修复：给 `tool0` 加惯性 + 对 `tool0_joint`/`camera_joint` 设 `preserveFixedJoint`；`git pull` 后重新 build 再跑 |
| `perception never produced a state` / `not calibrated yet: ...` | 感知节点要先等到深度图 + 机械臂静止（发射后先回 home 位）才开始标定。已修复：等待上限放宽到 120 s，并会每 3 s 打印一条 `not calibrated yet: <原因>`，照着原因排查即可 |
| `not calibrated yet: robot still moving (joint '...' position delta = 0.09)` | 机械臂到位后在缓慢下沉漂移：Gazebo 的位置命令接口是 P 控制器，默认增益 0.1 太小。已修复：URDF 里给插件加 `position_proportional_gain=10`，感知的静止阈值放到 0.15（Gazebo 在 WSL 下会残留 0.05~0.1 的速度噪声）。若仍报，请把这行发出来——它会告诉你是哪一个关节 |
| `TimeoutError: service /world_manager/reset_scene timed out`（demo 启动即退出） | 重置场景的删/建实体调用是在服务回调里阻塞执行的，Gazebo 还在加载机械臂时会很慢。已修复：世界管理器改用专门的辅助节点做阻塞调用、等 `/spawn_entity` 就绪、逐条打印 `spawned ag_obj_x`，demo 侧超时放宽到 120 s 并自动重试一次 |
| 抓取/推动服务调用超时 | 一条抓取计划包含多段轨迹，WSL 里仿真慢于实时（RTF≈0.3）会导致墙钟时间是仿真时间的 3 倍。已修复：`grasp/push/move_view` 超时放宽到 180 s，轨迹等待用 `spin_once` 轮询，保证回调里也能收到 action 结果 |
| Gazebo 闪退 / 黑屏 | WSL2 显示问题：Windows 11 用 WSLg；Windows 10 装 VcXsrv 并 `export DISPLAY=$(cat /etc/resolv.conf \| grep nameserver \| awk '{print $2}'):0` |
| 编译缺 `rosidl_default_generators` | 确认 source 了 `/opt/ros/humble/setup.bash` 再 colcon |
| OneDrive 目录里编译巨慢 | 把项目复制到 `~/ros2_ws/src`（9P 文件系统性能差） |

## 启动层

| 症状 | 处理 |
|---|---|
| 没有 Gazebo 窗口 | 看终端报错；`gui:=true` 是否被覆盖；确认 Gazebo 可单独启动（`gazebo`） |
| 机械臂不出现 | `spawn_entity.py` 超时：确认 robot_state_publisher 在跑、`/robot_description` 有话题 |
| `arm_controller` 不存在 | `ros2 control list_controllers` 看状态；controller_manager 日志 |
| 一直不打印 `perception ready` | 机械臂没到 home 或相机没数据：`ros2 topic hz /ag_camera/depth/image_raw` |
| 一直打印 `observe called before calibration` | 相机标定没完成；查 TF：`ros2 run tf2_ros tf2_echo base_link camera_link` |

## 相机与感知层

| 症状 | 处理 |
|---|---|
| 深度话题不存在 | `ros2 topic list \| grep ag_camera`；确认话题名与 perception.yaml 一致 |
| 深度全 0 或 NaN | 相机 min_depth/max_depth；物体是否在 0.05–2.0 m 内 |
| 标定出的镜像符号反了 | 高度图左右/上下颠倒：检查 `auto_calibrate` 日志打印的 signs，必要时在配置里固定 |
| 高度图大面积空洞 | 相机看不到桌面（默认视角太低/太远）；调 `execution.yaml` 的 `home_camera_pos/look` |

## 运动与抓取层

| 症状 | 处理 |
|---|---|
| IK 频繁失败 | 目标超出可达空间；换更近的位姿；增大 `seed_sets_flat` |
| 机械臂与桌子碰撞 | 运动原语路径不够安全：提高 `approach_offset` / `lift_height` |
| 抓不住物体 | 增加手指摩擦（URDF 里 `mu1/mu2`）、减小物体质量、降低闭爪速度 |
| 抓住后掉落 | 提升 `lift_height`、缩短搬运距离；检查回收盒边缘高度 |
| 服务返回 `success: false` | 看 execution_node 的 warn 日志，通常是 IK 或轨迹执行失败 |

## 训练层

| 症状 | 处理 |
|---|---|
| 每回合都超时且清理率恒 0 | 抓取成功率太低：先跑 demo 确认单次抓取可靠，再训练 |
| 奖励震荡不收敛 | 减小 lr（1e-4）、增大 replay 容量、调大 gamma 到 0.95 |
| 从不使用视角动作 | 视角奖励太小：增大 `env.py` 的 2.0 系数；或减小视角时间成本 |
| 视角用得太频繁 | 反之调小视角奖励、增大成本 |
| CPU 训练太慢 | 减小 `grid_width/height`（32×32）、减小网络 base_channels |
| 显存/内存不足 | 减小 batch_size 与 capacity |

## 通用调试三件套

```bash
ros2 topic list                      # 有哪些话题
ros2 topic hz /ag_camera/depth/image_raw   # 相机是否在发数据
ros2 service list                    # 服务是否注册
ros2 run tf2_ros tf2_echo base_link camera_link   # TF 是否连通
```

## 还没有解决？

把终端完整报错和上面三件套的输出一起发给导师/讨论区。**不要只贴最后一行**——
排查问题需要完整日志。
